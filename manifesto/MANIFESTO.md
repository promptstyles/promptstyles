# The Prompt Styles Manifesto

AI changed how software gets written. Technical interviews did not keep up. Some companies ban AI in interviews, others allow it with no criteria, and candidates rarely know what is being evaluated. Memorized puzzles measure less than ever, and nobody agrees on what should replace them.

We are engineers and people who hire engineers. We believe the craft did not disappear. It moved. It now lives in how we frame a problem, how we choose to direct the model, how we verify what comes back, and how we decide what ships. That can be named, taught and evaluated fairly.

## We value

- **Judgment** over volume of generated code
- **Verification** over blind trust in the output
- **Intentional choice of style** over a single prompting habit
- **Context** over clever phrasing
- **Open use of AI** over pretending it is not there
- **Real problems** over memorized puzzles

The items on the right still matter. The items on the left matter more.

## Principles

1. **Evaluate the process, not only the result.** In an AI-assisted interview, the final code is the least informative artifact. Watch how the candidate frames the problem, which style they pick, what they reject and why.

2. **Name the styles.** Declarative, imperative, spec-driven, test-driven, example-based, iterative, context engineering, vibe coding. A shared vocabulary lets candidates prepare and lets interviewers compare notes.

3. **No style is wrong. Choosing blindly is.** Good engineers move along the spectrum according to risk, complexity and how well they know the codebase. Vibe coding a prototype is fine. Vibe coding a payment flow is not.

4. **Verification is part of the job.** Reading, testing and questioning generated code is engineering, not overhead. Code the candidate cannot explain is not their code yet.

5. **Be transparent on both sides.** Companies say up front which AI tools are allowed, what is being evaluated and with which rubric. Candidates use AI in the open and explain their decisions.

6. **Keep it open.** The taxonomy and the rubric are public, versioned and free to adopt, adapt and criticize. Anyone can propose a change with a pull request.
